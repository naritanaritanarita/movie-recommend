各映画は `.c-content-item` のブロックに含まれる。

- タイトル: `h3.c-content-item__title a` のテキスト
- スコア: `.c-content-item-infobar__item--star .c-content-item-infobar__body` のテキスト
- 映画URL: `a` タグの `href` で `/movies/{id}` を含むもの（`#mark-...` フラグメントは除去して使う）
- 完全URL: `https://filmarks.com/movies/{id}` の形式

**Why:** 実際のHTMLで確認済み。ユーザーから提供されたHTMLに基づく。

**How to apply:** 次回HTMLが貼り付けられたらこのセレクターで優先的に解析する。構造が変わっていたら柔軟に対応してこのメモリを更新する。

## プロフィールページ（WebFetch経由）から取得する場合

ユーザーがHTMLを貼らず「プロフィールURLから取得して」と依頼するケースもある。`https://filmarks.com/users/<username>?page=N` は WebFetch で取得可能（filmarksドメイン許可済み）。

- 1ページあたり約36件。総マーク数はプロフィール上部に「NNNMarks」と表示される。ページ数 = ceil(総数/36)。
- 一覧ページ（`?page=N`）から取れるのは **タイトル・スコア・URL・（時々）公開年の帯**。ただし年はWebFetch要約が実際のFilmarksタグではなく本文から推測しているため誤ることがある（例: 実際は1961年版なのに一覧要約では2008年と誤抽出された事例あり）。
- **ジャンルは一覧ページには出ない**。`https://filmarks.com/movies/<ID>` を個別に WebFetch して「ジャンル」「日本公開年（上映日）」を取得する必要がある。
- **公開年は「日本公開年（上映日）」を使う**のが既存データとの整合性が高い（製作年ではなく）。4K修復版/リマスター版などの再上映作品は、再上映年ではなくオリジナル作品の公開年を使う（例: 「赤い風船 4K」→1956年、「恋する惑星 4Kレストア版」→1994年）。
- ジャンルは既存データに合わせて `/` 区切りで複数列挙する（例: `アクション/コメディ/SF`）。Filmarksのジャンルタグ順をそのまま使う。
- 新着順（マークした順）でページが並ぶため、既存 watched_movies.md の1行目のURLが一覧のどこに現れるかを見つければ、それ以降は全て重複と判断してページ取得を打ち切れる（全ページ個別チェック不要）。
- 未取得の全候補についてページ追記前に `grep "movies/<id> |" watched_movies.md` でURL重複チェックを行う。

**Why:** 2026-08-16にプロフィールURLからの取得依頼で実際に確認した挙動。

**How to apply:** 次回「プロフィールURLから取得して」と言われたら、まず既存ファイルの1行目URLを把握し、page=1から順に一覧取得→そのURLが現れたら打ち切り→新規分だけ個別ページでジャンル/公開年を補完する。
